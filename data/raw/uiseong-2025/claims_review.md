# 주장 매핑 검토 — 대응 기록 시차

작성: 2026-10-17. `logs/astra-consult-1.md`를 먼저 검토하고 `events.json` 70건의 인용문·19개 불일치 메모·admin/emd/KFS 자료를 대조했다. 결과는 **179개 주장, 원 사건 70건 모두 포함**이다. 동일 지표의 총계와 지역별 내역은 한 통계 주장으로 보존하고, 다른 행위·지표·장소별 시각은 분리했다. 모든 `quote`는 원 사건의 `sources[].quote` 전체를 그대로 복사했다. 인용문에 여러 사실이 함께 있는 경우 `notes` 첫 문장이 이 행에서 추출한 주장을 지정한다. 동일 원문 재사용은 독립 증거의 수가 아니다.

시각이 있는 행을 `event_time`, `claim_id` 순으로 정렬하고, null 행은 마지막에 `claim_id` 순으로 뒀다. 날짜만으로 자정을 만들지 않았다. 시간 없는 인용은 원 사건의 대표시각과 무관하게 `null/unknown`이며 알려진 사건 날짜는 notes에 남겼다. 정각만 명시된 시각은 `hour`; ‘께/쯤/전후’는 `approximate=true`다. 여기서 approximate는 **사건시각**의 근사 여부이며 면적·인원 추정 여부가 아니다. unknown의 false는 정확한 시각을 안다는 뜻이 아니다.

`published_time` 163건은 저장 원문 `data/raw/evidence/pages/`의 입력·등록·작성 시각을 직접 확인했다. 원 URL→캐시 파일 대응은 `scripts/build_events.py`의 SRC를 읽기만 했다. 입력/등록과 수정 시각이 모두 있으면 최초 입력/등록을 사용했으며, URL 숫자에서는 시각을 추출하지 않았다. 분까지만 표시된 게시시각의 ISO 초 `00`은 표기 정규화이고 초 단위 정밀도를 뜻하지 않는다. 근거 파일명과 표시 문자열은 각 notes에 있다. 나머지 16건은 공개일만 보존했다. PDF의 ‘즉시보도’, 회의시각, ‘10시 이후’나 보도 예정시각은 실제 게시시각으로 간주하지 않았다. 최초 기사등록시각은 현존 수정본의 모든 문장이 그때 이미 있었음을 보증하지 않는다.

`gov_document`는 확보된 정부 문서·정부 기고문, `gov_statement_via_press`는 정부·지자체·공공기관 발언/행위의 보도 또는 브리핑 전문 전재, `press`는 그 밖의 보도다. `official` 불리언을 그대로 복사하지 않았다. 시군 미특정·다지역이면 sigungu는 null, 유일한 시군을 식별하면 문자열, 두 시군을 잇는 e45a는 ‘영덕군·영양군’이다. 코드별 시군은 반드시 admin.json으로 조인한다.

## 1. 읍면동별 비교

시간은 모두 KST. 위성 시각은 검토 시점 `emd.json.properties.first_hit`를 그대로 사용한다. 기준점 `t0=2025-03-21T00:00:00+09:00`. 이 값은 읍면동 경계 안 첫 **열점 탐지**이며 실제 산불 도착·발화·최초 피해시각이 아니다. 위성 새 파생본이 생성되면 아래 표를 다시 계산해야 한다.

대응은 `alert_sms`, `evacuation_order`, `road_control`, `shelter_opened`를 기본으로 한다. 실제 대피 실행은 스키마에 별도 enum이 없으므로 `other`로 보존하고 표에는 보조로 포함했다(읍면 코드가 있는 e03a/e03b/e46a). 진화율·발화·피해·사망·기상·브리핑 장소는 대응으로 세지 않았다. 지휘본부 이전 e21d는 의성읍 행에 보조로 표시했다. 이 정의에 해당하는 **9개 읍면동을 모두 표시**했다.

## 3. derive_response.py 권장 출력 계약

분석 단위는 **읍면동 + 명시적으로 선택한 주장 쌍**이다. 무조건 읍면별 min(time)을 취하지 않는다. 시각 없는 더 이른 기록, 서로 다른 리, 다른 종류의 대응이 존재할 수 있다. 불완전한 기사 표본으로 최초 경보 지연, 실제 대피 가능시간, 지자체 순위/누락률을 만들지 않는다.

모든 시각은 timezone-aware ISO를 파싱한다. t0는 위와 같고, 분 단위 사건은 정수 분으로 변환한다. JSON 결측은 `null`; `unknown`은 표시문구/사유코드로 사용하고 숫자 필드에 문자열을 섞지 않는다. 원인 코드와 claim_id는 반드시 함께 내보낸다.

| `claim_event_t_min` | 해당 claim event_time−t0, 분. hour도 원문 정각의 명목 위치만 보존하고 precision을 동반 | event_time 없음; 타임존/형식 오류는 검증 실패로 처리 |

| `satellite_minus_spread_record_min` | first_detection_t_min − spread_record_t_min. 읍면 관측과 명명된 장소 기록의 명목 차이 | 양쪽 중 결측, 정밀도 부족, 코드 미확정. 음수도 보존(점곡−2555) |
| `satellite_minus_response_record_min` | first_detection_t_min − response_record_t_min. 양수=대응 기록이 첫 탐지보다 앞 | 양쪽 중 결측, 정밀도 부족, 대상코드 미확정 |
| `road_control_start_t_min` | 실제 통제 시작을 명시한 주장시각, 분 | e45a처럼 ‘통제 중’인 안내뿐이면 null. e24b/e32b는 route 단위로만 계산, 읍면별 null |
| `published_t_min` | source의 실제 확인된 최초 등록시각−t0, 분(초가 있으면 소수 보존) | published_time=null. published_date의00:00으로 대체 금지 |
| `publicly_available_by_selected_time` | Boolean. 명시적으로 검증한 해당 주장 버전이 선택시각까지 공개됐는가 | 기사 초기버전/수정 이력 미확보, 날짜만 있음, 선택시각 미정. 현재 claims의 등록시각만으로 true를 만들지 않음 |
| `gap_is_approximate` | Boolean. 계산에 쓰인 사건시각 중 하나라도 approximate이면 true | 대응하는 시차가 null. 오차폭을 ±1분/±30분으로 임의 생성 금지 |

각 pair에는 `emd_code`, `spread_claim_id`, `response_claim_id`, `response_action`, `response_time_role`(예: order_issued/sms_sent/control_started), `spatial_comparison`(emd/village_to_emd/route_endpoint_to_emd), `null_reasons` 배열, `source_urls`를 함께 제공한다. 이 필드는 별도 지표가 아닌 추적용 메타데이터다. 시각 충돌 여부나 `other`의 세부유형을 notes 문장 검색으로 자동 판정하지 말고 아래 검토 목록처럼 claim_id를 명시한다. 동일 리끼리 비교할 근거가 없는 쌍은 읍면 수준 비교임을 표시하고, 읍면 전체 도착/피난을 의미한다고 쓰지 않는다.

검토된 대응 pair 목록:

| 읍면 | spread_claim_id | response_claim_id | role | R−S / H−S / H−R (min) |
|---|---|---|---|---|
| 석보면 | e39a | e43a | order_issued | ≈67 / ≈225 / ≈158 |
| 석보면 | e39a | e45a | sms_sent, route endpoint | ≈89 / ≈225 / ≈136 |
| 지품면 | e39c | e45a | sms_sent, route endpoint | ≈29 / ≈165 / ≈136 |
| 길안면 현하리 | e25a | e25c | sms_sent, 시각 미상 | null / ≈558 / null |

길안면 백자리 e25b는 별도 satellite-only pair로 H−S≈506을 보존한다. 현하리 대상 e25c를 백자리 대응으로 연결하지 않는다. 풍천면 e34는 response-only, 점곡면 e24a는 spread-only로 각각 위성 차이만 보존한다. 이 목록 밖에는 자동 시간 조합을 만들지 않는다.

현재 first_hit의 센서 정보는 별도 재파생본을 읽어야 하며 이 작업에서는 바꾸지 않았다. 센서별 first_hit가 있는 최신 입력으로 재계산할 때 원문 주장의 시각·매핑은 유지한다. 시간대 변환·정렬·참조 코드·원문 일치 및 위 표의 산술은 검증했다. 행 수를 대응 발생 건수로 해석하지 않는다.
